# Story 069-A — Post-release change managed with same rigor as pre-release

> Parent: [[feature-069-devops-post-release-change-skill]].

As **DevOps managing post-release change**, I want **the same rigor as pre-release (specs kept current, comments updated, complexity tracked, dead code removed)**, so that **the legacy doesn't drift into the failure mode Jones observes (specs out of sync after ~5 years)**.

## Conditions of Satisfaction

- CR pipeline applies post-release.
- Renovation tool inventory (BP #47) available and used.
