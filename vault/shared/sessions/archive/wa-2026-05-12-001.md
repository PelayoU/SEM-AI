# Working Agreement · wa-2026-05-12-001

## Objetivo

Derivar el set inicial de capabilities desde los 7 goals aprobados, llenando el subgrafo estratégico entre `goals` y `features`. Vault de capabilities actualmente vacío.

## Approach

**Híbrido**: derivación top-down desde cada goal aplicando `capability-derivation` (OST de Torres + Rumelt + JTBD), seguida de **cross-check** con el bootstrap construido (`.claude/agents/`, `.claude/skills/`, `.claude/commands/`, `vault/shared/governance/`, `CLAUDE.md` raíz). El bootstrap es **evidencia operativa de jobs reales**: si una capability derivada no encuentra evidencia construida, es gap real; si una pieza construida no encaja en capabilities derivadas, es drift que se flagea (para WA de arbitraje posterior); si la derivación matchea con desviación de detalle, es ADR latente.

**3 categorías de drift** documentadas por capability (anclaje: Ford architectural drift detection):
- **(a)** Capability derivada SIN evidencia construida → goal pide cosa no construida (gap real, sano).
- **(b)** Pieza construida SIN encaje en capability derivada → feature implícita / over-engineering / capability faltante (necesita arbitraje posterior).
- **(c)** Capability derivada CON evidencia construida pero con desviación de detalle → ADR latente con `coherence-exception`.

## Fundamento bibliográfico

- **Torres — *Continuous Discovery Habits*.** Opportunity Solution Tree: outcome → oportunidades → 2-3 soluciones por oportunidad.
- **Rumelt — *Good Strategy/Bad Strategy*.** Kernel estratégico (diagnosis + guiding policy + coherent action): filtro de capabilities por coherencia con guiding policy.
- **Christensen — Jobs-To-Be-Done.** Oportunidades articuladas como jobs ("el usuario no puede / sufre / necesita X").
- **Cagan — *Inspired* + *Empowered*.** Strong product team multi-rol; preview de viability/usability/business/quality desde el discovery.
- **Bass — *Software Architecture in Practice*.** Quality attributes + tactics + tradeoffs aplicados a cada capability.
- **Ford et al. — *Building Evolutionary Architectures*.** Fitness functions + architectural drift detection (3 categorías a/b/c).
- **Nygard — *Documenting Architecture Decisions*.** ADRs latentes detectables pero no escritos hasta que el WA dedicado los procese (regla "una decisión = un ADR").
- **Patton — *User Story Mapping*.** Slicing y narrative flow aplicado más adelante en feature-design (este WA prepara el terreno).
